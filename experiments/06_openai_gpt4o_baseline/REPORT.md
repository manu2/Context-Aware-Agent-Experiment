# Empirical Evaluation Report: OpenAI GPT-4o vs. Google Gemini 3.7 Flash

**Experiment:** Substrate & Self-Telemetry Conditioned Agentic Computation (SCAC) Multi-Model Benchmark  
**Date:** August 2026  
**Target Workload:** High-Dimensional Pairwise Euclidean Distance (`vectors.npy`, 8,000 x 1,024 float32 matrix)  
**Container Limit:** 128 MB RAM (`cgroup v2 MemoryMax=128M`)  
**Models Evaluated:** OpenAI `gpt-4o` vs. Google `gemini-3.7-flash`

---

## 1. Executive Summary & Core Discovery

When presented with identical tasks under strict 128 MB RAM constraints, **frontier LLMs exhibit starkly different degrees of "Silicon Blindness"**:

* **Google Gemini 3.7 Flash**: Demonstrates **Active Quantitative Sensitivity**. When presented with `RAM limit: 128 MB`, it dynamically switches from full-matrix broadcasting to memory-bounded row streaming or **2D Block Tiling** ($B=2000$), reducing peak RSS from $1,565.7\text{ MB} \rightarrow 69.8\text{ MB} - 114.8\text{ MB}$ (100% survival rate inside 128MB containers).
* **OpenAI GPT-4o**: Exhibits **Persistent Silicon Blindness**. Across all four prompt conditions (Blind, Natural Language, 1D Telemetry, and 2D Telemetry), GPT-4o persistently defaults to eager $O(N^2)$ dense matrix multiplication (`np.dot(matrix, matrix.T)`), allocating **$770.36\text{ MB} - 1,136.31\text{ MB}$ heap RSS**. In a real 128MB container, **all 4 variants generated by GPT-4o suffer instant Linux kernel `SIGKILL (Exit 137 OOM)` kills**.

## 3. Algorithmic Breakdown & Code Comparison

### A. Gemini 3.7 Flash Behavior (Variant D - 2D Telemetry)
Gemini computed the memory footprint and synthesized Level-3 BLAS 2D Block Tiling:
```python
# Gemini 3.7 Flash (Variant D) -> Synthesizes 2D Block Tiling to respect 128MB:
block_size = 2000
for i_block in range(num_blocks):
    V_A = V[i_start:i_end, :]
    for j_block in range(i_block, num_blocks):
        V_B = V[j_start:j_end, :]
        dot_matrix = V_A @ V_B.T  # Matrix size: (2000, 2000) * 4 bytes = 16 MB
        dist_sq = V_A_sq[:, None] + V_B_sq[None, :] - 2 * dot_matrix
        total_distance += np.sum(np.sqrt(np.maximum(dist_sq, 0.0)))
```
* **Result**: Peak RAM = **114.84 MB**, Latency = **0.46s** (fits inside 128MB sandbox).

### B. OpenAI GPT-4o Behavior (Variant D - 2D Telemetry)
GPT-4o ignored the `RAM limit: 128 MB` constraint and wrote monolithic un-chunked matrix operations:
```python
# OpenAI GPT-4o (Variant D) -> Monolithic eager broadcast:
def compute_total_pairwise_distance(matrix):
    squared_norms = np.sum(matrix ** 2, axis=1)
    dot_product_matrix = np.dot(matrix, matrix.T)  # Matrix size: (8000, 8000) * 8 bytes = 512 MB
    squared_distances = squared_norms[:, np.newaxis] + squared_norms[np.newaxis, :] - 2 * dot_product_matrix
    return np.sum(np.sqrt(squared_distances))
```
* **Result**: Peak RAM = **770.41 MB** $\rightarrow$ **Instant `SIGKILL Exit 137 (OOM)` under 128MB container ceiling**.
